# 자원·시간·RTOS 판단 기록

|자원|현재 사용자|추가 기능 요구|공유·충돌 근거|처리 정책·시험|
|---|---|---|---|---|
|PA4|기존 ADC 입력|미정|ADC/SPI1NSS/DAC 모드·실물 회로|미정|
|PB12|기존 LED|미정|SPI2NSS/터치/온보드 연결|미정|
|PA9|기존 USART1TX|보고 길이 증가|9600/8N1·기존 문장|최대 길이·혼합 형식 거절 시험|
|시간원|기존 TIM2 IRQ의ms_tick|완료 관찰tick|IRQ 지연과 실제CNT 구분|같은 지점에서기록·실측별도|
|RAM|큐·active·문자열|seq·tick추가|구조체padding·정렬 포함sizeof/Map|초기화·복사·범위확인|
|DMA/IRQ|현 프로젝트확인|이번에는미도입|다음 단원에서매핑확인|미실행|

- 현재 시간 요구: 시작·끝 사건, 주기/허용지연/근거, 장비·관측 지점:
- 긴 폴링·IRQ 마스크·버스/저장 장치 대기·순간 부하·큐 포화 여부:
- 같은 조건의 기존 실행과 변경 후 실행 증거:
- 작업 분할·상태 처리·큐 정책으로 해결 가능한가:
- RTOS가 필요하다면 태스크/우선순위/스택/공유자원/시간원/ISR API 설계 범위:
- 결정: 이번에는보류 / 선행학습 / 도입제안. 근거가 없으면 성능개선완료로표기하지않음.

RTOS가 물리 선로 대역폭·장치 대기시간을 줄인다고 가정하지 않는다. 현재는 포트·태스크 구현과 실측이 없다.
